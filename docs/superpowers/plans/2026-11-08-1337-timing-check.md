# chreode timing check Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `@mindlace/chreode` v0.4.0 with `chreode timing-check` and `timingStep()`: a signoff step that fails when a branch's added test lines introduce a fixed wait, a raised timeout, raised retries or an unconditional skip.

**Architecture:** A new `src/timing/` package mirrors `src/burn-in/`: `diff.ts` parses `git diff --unified=0` into hunks (pure), `rules.ts` and `values.ts` evaluate one hunk at a time (pure, net-new per hunk), `check.ts` applies `match`/`perf`/`disable`/`allow` (pure), `report.ts` formats output (pure), `run.ts` is the only module that calls git (through the injectable `Exec`) and is the CLI command, `step.ts` is the config helper. Config gets an always-resolved `timing` block.

**Tech Stack:** Node ≥ 22.12, TypeScript ~6.0 strict NodeNext, commander 15, picomatch 4 (via `matchesAny`), vitest 4. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-08-1337-timing-check-design.md` (read it before starting any task). Style reference: `docs/superpowers/plans/2026-10-11-2056-flakes.md`.

## Review Focus

1. **Hunk content that looks like a header.** With `--unified=0`, a removed line whose text starts with `--` (a SQL or shell comment in a fixture, a `--retries=2` CLI arg on its own line) appears as `--- …`, and an added `++i` appears as `+++i`. A parser that treats those as file headers drops or misattributes lines. Expect each hunk to consume exactly the line counts its `@@` header declares. (Task 2 pins it.)
2. **`timeout: 0` means "never time out".** In Playwright and vitest, 0 disables the timeout. A hunk that lowers `timeout: 30_000` to `timeout: 0` looks like a decrease and is the biggest raise possible. Expect 0 to compare as infinity. (Task 4 pins it.)
3. **The developer's git config.** `diff.noprefix`, `diff.mnemonicPrefix`, `color.diff=always`, an external diff driver, `diff.relative` or `core.quotePath` change `git diff`'s output on one machine and not another, and the verdict with it. Expect the diff to be requested with every output-shaping option pinned on the command line. (Task 5 pins the exact argv; Task 2 parses a path with a space, which git suffixes with a tab, and a quoted path.)
4. **An `allow.pattern` with the `g` or `y` flag.** `RegExp.test` on a global regex carries `lastIndex` between calls, so the same entry would alternately match and miss consecutive identical lines. Expect every line to be tested fresh. (Task 4 pins it in `checkTiming`.)
5. **Comments that name a banned API.** `// don't use page.waitForTimeout(…) here` or `* test.skip('…') hides the bug` in a JSDoc block is documentation, not a crutch; flagging it teaches people to add exemptions by reflex. Expect lines whose trimmed text starts with `//`, `/*` or `*` to be ignored by every rule. (Task 3 pins it.)

## Resolved gaps and builder's calls

- **No `--base` flag.** The spec's _Shape_ section shows `--base <sha> --head <sha>`; its _Reading the diff_ section (the later, more specific ruling) says there is no `--base` and the range is `origin/<baseBranch>...head`. This plan follows _Reading the diff_.
- **No pathspec on `git diff`** (builder's call): the spec writes `-- <matched paths>` but then says to filter after the diff, since a `RegExp` matcher cannot be a pathspec. The whole branch diff is parsed and filtered in `checkTiming`.
- **Comment lines are ignored by every rule** (builder's call; Review Focus 5): the anti-goal "a check that cries wolf".
- **Matching is per line**: a line counts once per rule however many matches it holds (builder's call: net-new compares line counts, and a line is what the output reports).
- **Value rules pair settings by key, in order, within a hunk** (builder's call; the spec fixes the comparison, not the pairing): the i-th added `timeout:` is compared with the i-th removed `timeout:`; added settings beyond the removed count are flagged ("any value when the hunk removes none"). A paired setting whose value text is unchanged (whitespace-normalized) is never flagged, even when not evaluable, so a Prettier rewrap of `timeout: TIMEOUT_MS` is quiet. A paired setting whose text changed and either side is not evaluable is flagged.
- **`test.slow(`** has no value: it is a count-only setting (net-new by count, like `fixed-wait`).
- **An added retries value of literal `0` is never flagged** (builder's call): turning retries off is the opposite of the crutch. This narrows the spec's "adds one where there was none".
- **`skip` also covers `test.describe.fixme(` and `xtest(`** (builder's call: the same crutch, other spellings).
- **Fix pointer** (builder's call): the output's `Fix:` line links `<playbookUrl>#the-playbook`, where `playbookUrl` is `flakes.playbookUrl` when a `flakes` block exists, else `DEFAULT_PLAYBOOK_URL`. The spec's example `docs/flakes.md#the-playbook` is a path in chreode's repo, which does not exist in a consumer's checkout.
- **Exemption output is one line per used `allow` entry**, naming the rule, the line count, the files and the reason (builder's call: chreode's own fixtures exempt many lines; one line per entry stays readable while hiding nothing).
- **No `git fetch`** in `timing-check` (builder's call): signoff fetched already; by hand the user's local `origin/<baseBranch>` is the reference. If it does not exist, git's error propagates and the CLI exits 1.
- **chreode's own step runs `node dist/cli.js timing-check`**, overriding `timingStep`'s `run`, because chreode is not installed in its own `node_modules` (`npm run signoff` builds `dist/` first). The real-git test lives in `src/timing/run.spec.ts`, so chreode's `allow` scope stays exactly `src/timing/**/*.spec.ts` as the spec says.

### Task 2: Diff parsing

**Files:**

- Create: `src/timing/diff.ts`
- Test: `src/timing/diff.spec.ts`

**Interfaces:**

- Produces:
  - `interface AddedLine { line: number; text: string }` — `line` is the new-file line number.
  - `interface Hunk { removed: string[]; added: AddedLine[] }`
  - `interface FileDiff { path: string; hunks: Hunk[] }`
  - `function parseDiff(out: string): FileDiff[]` — files in diff order; a file with no hunks (binary, mode-only) is omitted.

Parsing contract: a file starts at `diff --git`; its path comes from the `+++ b/<path>` line (strip the `b/` prefix and one trailing `\t`; a path in double quotes is C-unquoted: `\\`, `\"`, `\t`, `\n`, and `\NNN` octal bytes decoded as UTF-8). A hunk starts at `@@ -a[,b] +c[,d] @@` (missing count means 1) and then consumes exactly `b` lines beginning `-` and `d` lines beginning `+`, in that order, skipping any `\ No newline at end of file` line; added line numbers run from `c`. Line text drops the leading marker and one trailing `\r`.

- [ ] **Step 1: Write the failing tests**

Build diff fixtures as arrays joined with `'\n'`. Tests:

- `numbers added lines from the hunk header` — a modified file with hunks `@@ -10,2 +10,3 @@` and `@@ -40 +41 @@` → `[{ path: 'e2e/a.spec.ts', hunks: [{ removed: [r1, r2], added: [{line: 10,…},{line: 11,…},{line: 12,…}] }, { removed: [x], added: [{ line: 41, … }] }] }]`.
- `reads a new file` — `--- /dev/null`, `@@ -0,0 +1,2 @@` → `removed: []`, lines 1 and 2.
- `consumes hunks by their declared counts` (Review Focus 1) — a hunk `@@ -3,2 +3,2 @@` whose removed lines are `--- legacy comment` and `-  ++i;` (raw diff lines `---- legacy comment`, `--  ++i;`) and added lines `++++j;`, `+-- note` → removed `['--- legacy comment', '  ++i;']`, added texts `['+++j;', '-- note']`, and the next `diff --git` file is still parsed.
- `strips the tab git appends to a path with a space` — `+++ b/e2e/my flow.spec.ts\t` → `path: 'e2e/my flow.spec.ts'`.
- `unquotes a quoted path` — `+++ "b/e2e/say \"hi\".spec.ts"` → `e2e/say "hi".spec.ts`; `+++ "b/e2e/caf\303\251.spec.ts"` → `e2e/café.spec.ts`.
- `ignores the no-newline marker and CRLF` — `+await x();\r` then `\ No newline at end of file` → text `await x();`, count respected.
- `omits files without hunks` — a `Binary files /dev/null and b/e2e/shot.png differ` entry → not in the result.
- `parses empty output` → `[]`.

### Task 3: Count rules — `fixed-wait` and `skip`

**Files:**

- Create: `src/timing/rules.ts`
- Test: `src/timing/rules.spec.ts`

**Interfaces:**

- Consumes: `Hunk`, `AddedLine` (Task 2); `TimingRuleId` (Task 1).
- Produces:
  - `interface Finding { rule: TimingRuleId; line: number; text: string; was?: string }` — `text` is the added line, trimmed; `was` is the paired removed value text (value rules only).
  - `function isComment(text: string): boolean` — trimmed text starts with `//`, `/*` or `*`.
  - `function netNew(hunk: Hunk, rule: TimingRuleId, matches: (text: string) => boolean): Finding[]` — counts non-comment matching lines among `removed` (R) and `added` (A) and returns the **last** `max(0, A − R)` matching added lines.
  - `function evaluateHunk(hunk: Hunk, rules: readonly TimingRuleId[]): Finding[]` — runs each listed rule, results sorted by `line` then rule order. In this task it knows `fixed-wait` and `skip`; Task 4 adds the other two.

Rule intent (regexes are the builder's; every case below must hold):

- `fixed-wait` matches a line calling `waitForTimeout(`, a `new Promise(` that calls `setTimeout(` on the same line, `sleep(`, `delay(` (word-bounded, so `retryDelay(` does not), or `wait(` with a numeric first argument. A line that also calls a fake-timer API (`vi.advanceTimersByTime`, `vi.advanceTimersByTimeAsync`, `vi.runAllTimers`, `clock.tick`, or any `.clock.` member such as `page.clock.runFor`) never matches.
- `skip` matches `test.skip(`, `it.skip(`, `describe.skip(`, `test.fixme(` whose first argument is a string literal (`'`, `"`, `` ` ``) or empty (`()`), and `test.describe.skip(`, `test.describe.fixme(`, `xit(`, `xtest(`, `xdescribe(` with any arguments.

**Interfaces:**

- Consumes: `Hunk`, `FileDiff` (Task 2); `Finding`, `netNew`, `isComment`, `evaluateHunk` (Task 3); `ResolvedTiming`, `TimingAllowEntry`, `TIMING_RULE_IDS` (Task 1); `matchesAny` (`src/signoff/plan.ts:63`).
- Produces:
  - `values.ts`: `function parseValue(expr: string): number | null` — integer literals with `_` separators, and products of them (`30 * 1000`, `2 * 60 * 1000`); `0` returns `Infinity`; anything else `null`. `function timeoutRaise(hunk: Hunk): Finding[]`, `function retriesRaise(hunk: Hunk): Finding[]`.
  - `check.ts`: `interface Violation extends Finding { path: string }`; `interface UsedExemption { entry: TimingAllowEntry; violations: Violation[] }`; `interface TimingResult { checked: string[]; violations: Violation[]; exempted: UsedExemption[] }`; `function isTimingChecked(path: string, timing: ResolvedTiming): boolean` (matches `match`, not `perf`); `function checkTiming(files: readonly FileDiff[], timing: ResolvedTiming): TimingResult`.
  - `report.ts`: `function formatTimingReport(result: TimingResult, playbookUrl: string): string[]`.

Value rule contract (both rules): extract settings `{ key, value }` from each non-comment line; group by key; pair the i-th added with the i-th removed setting in the hunk. Flag an added setting when it is unpaired, or paired and its whitespace-normalized value text differs and either `parseValue` is `null` or added > removed. A flagged paired setting carries `was` = the removed value text as written. Keys:

- `retries-raise`: `retries:`, `retry:`, `--retries=`, `--retry=` (key `retries` or `retry`, whichever is spelled; `--retries=2` and `retries: 2` share key `retries`). An added value that is literally `0` is never flagged.
